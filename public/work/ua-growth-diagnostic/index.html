案例：出海游戏 UA 增长数据诊断#

背景#

出海游戏团队在规模化买量后，常见问题不是「没有数据」，而是数据太多、口径太散、系统之间互相解释不清：

  • 媒体后台、MMP、BI 的 spend、install、revenue、ROI 对不上
  • Campaign 命名和层级变化导致 cohort 历史不可比
  • iOS SKAN、user-level 归因和广告变现收入混在一起解释
  • 优化师每天看多个后台，但动作缺少效果追踪

核心判断#

买量诊断不能只看 ROI 报表，要同时检查四条链路：

  1. 广告平台链路：账户、campaign、adset、creative、spend、action history
  2. MMP 归因链路：AppsFlyer / Adjust / Singular 的 cost、cohort、SKAN、raw data
  3. 游戏事件链路：SDK 初始化、event taxonomy、IAP / ad revenue、S2S 去重与延迟
  4. BI 决策链路：指标口径、更新 SLA、维度表、dashboard 分层、异常说明

方案#

建立一次本地诊断数据房间：

UA Diagnostic Data Room
  ├─ raw/                  # 原始导出或 API 响应
  ├─ db/ua_diagnostic.db   # SQLite / DuckDB
  ├─ scripts/              # fetch / import / analyze 脚本
  ├─ mappings/             # media / campaign / geo / creative 映射
  ├─ metrics/              # 指标口径定义
  ├─ checks/               # 数据质量检查
  └─ reports/              # 诊断报告与图表

围绕四个评分输出：

  • Data Trust Score：数据可信度
  • UA Efficiency Score：买量效率
  • Attribution & Event Chain Gap：归因和事件链路缺口
  • Decision System Maturity：决策系统成熟度

可复用方法#

  • 先做 read-only 诊断，不直接改后台
  • 原始数据、本地脚本、指标口径和图表全部可复跑
  • 区分管理层看板、UA Lead 看板和优化师工作台
  • 每个投放动作必须形成 action tracking：动作前、动作后、预期、结果

典型输出#

  • 数据可信度评分与风险解释
  • 低 ROI 持续消耗 campaign 清单
  • 高 ROI 但未扩量 GEO / campaign 机会清单
  • 素材疲劳与新素材测试不足清单
  • 归因口径、事件回传、BI SLA 的修复优先级
